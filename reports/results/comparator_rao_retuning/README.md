# Comparator retuning on vessel RAO motion

Baseline: `e4d8586e78070922e2782066330520e4f7b17423`.
OU-III is a frozen reference: this experiment does not change its filter,
configuration, injected sensor histories, or quality gates.

Each candidate runs the complete eight pinned v1.2.1 28 ft vessel RAO records
(JONSWAP and PM-Stokes, four incident wave heights). Scores use the final
900 seconds of each 1200-second record. Round 1 screens individual coefficients;
round 2 refines their useful ranges; subsequent rounds examine combinations.
Finalists are compared with the baseline on additional paired sensor and
initialization draws before defaults are selected. These are new sensor draws
on the same motion records, not independent sea realizations or unseen hulls.

Selection considers unchanged gate failures first, then displacement and
attitude errors across all records. Means cannot conceal individual regressions:
retained run files contain record-level metrics and failures. NLO has no
absolute-heading reference in this configuration, and its yaw is not scored.
Coefficient sweeps use reference trajectories offline; online gain scheduling
uses only the estimator's measured inputs.

Configurations in `*-round*.json` are overrides of the baseline executable,
not multipliers to apply again after changing defaults. The existing sweep
runners retain binary hashes, producer hashes, input hashes, settings, and
source revisions. Flat response to a coefficient is reported as such, rather
than counted as a tuning improvement.

The starting OU-II and PII simulators override some library coefficients.
Consequently the initial comparison baseline means the current published
simulation configuration. Selected tuning must be carried into library defaults
and the corresponding simulator overrides removed before final validation.

## Selected settings

| Method | Parameter | Previous simulation setting | Selected library default |
|---|---|---:|---:|
| OU-II | Gyro process-noise standard-deviation weight | 1 | 0.2 |
| TFG | Acceleration-model scale | 1 | 0.8 |
| NLO | Wave-frequency gain multiplier | 0.56 | 0.5575 |
| PII | Reference pole rate, 1/s | 0.08125 | 0.08775 |
| PII | Acceleration smoothing time, s | 0.40 | 0.42 |
| PII | Mahony integral gains, base/calm/rough | 0.0225 / 0.025 / 0.0175 | 0.01125 / 0.0125 / 0.00875 |

The previous OU-II simulation-only profile (tau multiplier 0.95, pseudo-channel
ratio 0.5, and stillness decay 5 s) is now the library default. Its gyro weight
multiplies the configured standard deviation before covariance construction;
measurements and injected sensor errors are unchanged. The PII simulator now
uses the shipping configuration instead of maintaining a second tuning table.
Hardware-specific sensor specifications remain supplied by each application.

OU-II's held-out mean 3-D error falls from 0.369193 to 0.367063 m; mean roll,
pitch, yaw and normalized heave also improve. PII's held-out normalized heave
falls from 5.78780 to 5.74423 percent Hs, with improved mean attitude errors.
TFG's heave improvement is small (3.84054 to 3.83491 percent Hs); 3-D error,
pitch and yaw have small adverse changes. NLO's heave improvement is also
small (7.09517 to 7.09269 percent Hs), with slightly larger tilt error.
No claim of improvement in every record or every metric is made.

The OU3-like OU-II anisotropic setting (0.72, 0.50) was tested and rejected:
default-draw mean 3-D error increased from 0.371679 to 0.383743 m, despite
better mean yaw and pitch. NLO's 40 s gain smoothing alone was rejected after
it added a held-out violation. Its unsuccessful holdout is retained separately.
The final NLO gain was frozen before new draws 63001 and 64007; the other
families use held-out draws 61001 and 62003. Draws default, 11 and 23 were
available during refinement. `selection.json` records this split.

`sweep-results.md` and `sweep-summary.json` are generated by
`python3 tools/comparator_tuning_report.py`. Aggregate `runs.json` files retain
every record/seed metric and failure; redundant individual logs and JSON are
omitted. Use `*-current-default-replay.json` to restore the previous simulation
setting and compare it with the selected defaults in a newly built executable.
