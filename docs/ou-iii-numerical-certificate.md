# OU-III numerical source-funnel certificate

This workflow instantiates the OU-III stability analysis against the **unchanged adaptive filter** and the same eight noisy stationary reference records used by the validation suite.

The certificate has one non-negotiable rule: estimator stability transitions are never identified by regressing noisy truth-error trajectories. The host observer records the closed-loop maps and covariance generated by the estimator itself. Truth is used only to score filter error and replay-domain occupancy.

## Claim levels

The pipeline keeps four claims separate.

1. **Filter regression.** The unchanged adaptive OU-III implementation must pass its ordinary RMS/quality gates on all eight noisy records.
2. **Exact executed-source linear certificate.** Exact same-mode Live words are composed from the estimator's implemented prediction/correction/reset maps. Their source-varying Lyapunov metric is the actual estimator information matrix, `M(g)=Sigma_KF(g)^(-1)`.
3. **Numerical nonzero-neighborhood certificate.** A nonlinear SO(3) word map, startup/hybrid funnel, and disturbance bounds must close on a nonzero neighborhood. Executed nominal/noisy replay is diagnostic evidence and cannot establish this level by itself.
4. **Deployment theorem certificate.** Complete continuous source families must be enclosed with validated arithmetic, with strict uniform linear, nonlinear, hybrid, and stochastic margins.

A stable simulation, an exact executed linear contraction, and a deployment theorem therefore never share one PASS bit.

## Exact closed-loop maps

The host observer consumes matrices that the MEKF actually used:

- `F_AA_scratch_` for attitude/gyro-bias prediction;
- `F_LL_scratch_` for the exact `(v,p,S,a_w)` OU chain;
- the active/held accelerometer-bias transition;
- `PCt_scratch_ = P H^T` and `K_scratch_` for accepted measurements;
- the periodic `S=0` correction with full `P(:,S)`;
- the left-error reset transport after quaternion injection.

For an accepted correction,

\[
A_k^{\rm corr}=G_k(I-K_kH_k).
\]

The map follows implementation order exactly: prediction, any due `S=0` correction, accelerometer update, asynchronous magnetometer updates, and reset transport. Blocks that cross bias release or magnetic gauge changes are marked hybrid and excluded from ordinary same-mode words.

The replay stage also checks a map-reconstruction residual. A stale or incorrectly ordered map is therefore an instrumentation failure, not a stability result.

## Held and active modes

Normal Live operation has two fixed-dimensional coordinates:

\[
e_H=(\delta\theta,b_g,v,p,S,a_w)\in\mathbb R^{18},
\]

\[
e_A=(\delta\theta,b_g,v,p,S,a_w,b_a)\in\mathbb R^{21}.
\]

Words never multiply across this dimensional change. Bias release is a hybrid transition with its own destination-domain obligation.

## Source-varying Kalman information metric

The primary linear certificate no longer forces transient Riccati states into one coarse node metric. For every exact word it uses

\[
M(g)=\Sigma_{\rm KF}(g)^{-1}.
\]

Let `Phi_w` be the exact deterministic closed-loop error map over a same-mode word, and let `Sigma_0`, `Sigma_1` be the estimator covariance at its endpoints. The implemented prediction/Joseph recursion gives

\[
\Sigma_1=\Phi_w\Sigma_0\Phi_w^T+\Omega_w.
\]

Define

\[
\delta_w:=\lambda_{\min}\!\left(
\Sigma_1^{-1/2}\Omega_w\Sigma_1^{-1/2}\right).
\]

Then, exactly,

\[
\boxed{
\lambda_w^{\rm info}
=\lambda_{\max}\!\left(
\Sigma_0^{1/2}\Phi_w^T\Sigma_1^{-1}\Phi_w\Sigma_0^{1/2}
\right)
=1-\delta_w.}
\]

Hence `delta_w>0` is not merely correlated with contraction; it **is** the strict contraction margin in the source-varying information metric.

`tools/ou3_information_certificate.py` independently computes both sides and checks their numerical identity. It also records lower/upper covariance eigenvalue bounds so the varying information metric can be compared uniformly with the Euclidean local error norm.

Candidate word horizons are

`0.25, 0.5, 1, 2, 4, 8, 16 s`.

The linear report preserves:

- the first horizon with a strict executed-source contraction;
- every tested horizon;
- the strongest tested executed contraction margin;
- the worst relative Riccati injection margin;
- covariance endpoint eigenvalue/condition bounds;
- map/covariance alignment and identity residuals.

A PASS here means **exact executed-source linear contraction**. It does not yet prove a continuous-source neighborhood.

## Executed noisy funnel accounting

`tools/ou3_information_completion.py` evaluates truth error in the same source-varying information metric,

\[
W_k=e_k^T\Sigma_k^{-1}e_k.
\]

For a certified horizon it forms the executed noisy affine envelope

\[
W^+\le\lambda W^-+\gamma.
\]

The asymptotic fixed point is

\[
b_*={\gamma\over 1-\lambda}.
\]

Finite entry from above cannot be claimed into `b_*` itself. The implementation therefore declares a strict superlevel

\[
b_\eta=b_*(1+10^{-3})+10^{-12}>b_*
\]

and computes finite capture only into `b_eta`. This distinction is covered by unit tests.

For replay accounting the tool evaluates every already-certified contracting horizon and chooses the one with the smallest `b_*`; it does not automatically use the first linear contraction horizon.

The report also records startup handoff and executed hybrid amplification. These are **executed-replay facts**, not validated inequalities over a neighborhood.

## What remains for a nonzero-neighborhood certificate

The current exact linear certificate substantially narrows the remaining problem. The next numerical producer must work on the exact nonlinear source word and establish, on a nonzero source-domain neighborhood:

- a geodesic chart bound `theta_star < pi`;
- exact nonlinear word decrease, or an equivalent positive `mu_W` margin;
- prefix safety throughout each word;
- startup handoff into a certified destination sublevel;
- held-to-active and magnetic gauge/refinement jump inequalities;
- tilt-reset/cooldown jump inequalities where source reachable;
- non-empirical disturbance/noise constants.

A dense perturbation search may be used to find the likely active constraint, but it cannot promote the theorem. Promotion requires validated enclosure/branch-and-bound or equivalent outward-rounded arithmetic.

## Continuous-source linear promotion

The information identity gives a simpler deployment target than the obsolete coarse fixed-node LMI route. For each fixed-dimensional mode it is sufficient to validate over a source-complete word family:

1. a uniform positive relative injection margin
   \[
   \delta_w\ge\delta_*>0;
   \]
2. uniform covariance metric bounds
   \[
   0<\underline\sigma I\preceq\Sigma(g)\preceq\overline\sigma I<\infty;
   \]
3. finite source-prefix gain.

Then every word boundary satisfies

\[
W^+\le(1-\delta_*)W^-,
\]

and bounded word length plus finite prefix gain gives UES of the homogeneous fixed-mode recursion on the validated source family.

The old fixed-node/group-compatible SDP remains useful only as a diagnostic/comparison route; it is not the primary executed-source linear certificate.

## Deterministic scientific results

Files below `reports/results` are part of scientific result fingerprints. They must depend only on input data and repository code/configuration.

Therefore:

- scientific JSON contains no CI run/build/artifact IDs;
- scientific JSON contains no wall-clock generation timestamps;
- JSON is emitted with stable sorted keys;
- raw simulator stdout/stderr logs are **not** stored below `reports/results` because they contain workspace-specific paths;
- raw logs are written under `reports/diagnostics/ou3_numerical_certificate/` and uploaded as a separate diagnostic artifact;
- `tools/ou3_result_contract.py` checks generated JSON and rejects raw `.log` files inside the scientific result tree.

Physical simulation time such as `time_s` is allowed because it is determined by the input record and simulation code, not by execution time.

## Reading a failure

The first active obstruction is the scientific result:

- RMS/quality failure -> filter regression problem;
- exact-map residual or map/covariance alignment failure -> certificate instrumentation problem;
- no strict information contraction at tested horizons -> local/source-word dynamics or source-family problem;
- executed linear contraction passes but nonlinear neighborhood does not -> nonlinear certificate bottleneck;
- nonlinear words pass but startup/hybrid destination inequalities fail -> handoff/hybrid bottleneck;
- deterministic neighborhood passes but stochastic localization is ineffective -> stochastic bound bottleneck;
- numerical neighborhood passes but validated continuous-source injection/covariance bounds fail -> source-envelope/theorem conservatism bottleneck.

## Ultimate question

The final question remains:

**Does the current adaptive OU-III filter pass its performance tests, enter a numerically verified stability neighborhood on all eight noisy reference seas, and satisfy the complete source-reachable deployment theorem?**

The pipeline reports each layer separately. Until the nonzero-neighborhood and validated continuous-source stages close, the correct final status is **certificate incomplete**, even when the filter regression, exact executed-source linear certificate, and executed replay accounting all pass.
